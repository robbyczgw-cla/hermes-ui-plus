# products (shopping, product comparison, "Top N" lists)

The block IS the node: `{"type":"products",...}` at top level, never an envelope (`{"version","blocks":[...]}`), array or wrapper. Key is `products` (not `items`), entry title is `name` (not `title`). Load this once, then research.

Photos (hard): EVERY extract call on a shop, maker or review page sets your extract tool's image option (`web_extract_plus`: `include_images: true`), then copy that page's main image into `image` (details below).

Data rules (hard): data ONLY from tools (web search, maps, shop pages) or what the user gave, never from memory. NEVER invent ratings, review counts, prices, hours, phones, addresses, coordinates, URLs: unknown = LEAVE THE FIELD OUT (no "n/a", no guess). `source` (e.g. "Websuche, abgerufen 11.10.2026") + `basis:"sourced"` required. A tool gave nothing: say so in text, no node. Text first: 1-3 sentences with your pick and why OUTSIDE the node; the node shows details, don't repeat them as prose.

Photos: ALWAYS `imageQuery` on every item (brand + model; the app's fallback). `image` (optional) = the product photo of a shop/maker/review page you fetch anyway for the data: when your extract tool can return page images, turn that on (`web_extract_plus`: `include_images: true`; other extract tools: their image option, if any) and copy ONE returned https URL, the page's main image (og:image / product hero). Never logos, icons, sprites, banners, ads, avatars, tracking pixels (1x1, "pixel", "beacon"), placeholders, `data:`/base64, or a URL you built, shortened or guessed. The tool returned no image: leave `image` out (the app searches by `imageQuery`). Never fetch a page only for its image. `website`/`url`/`offers[].url` = https from a tool only.

Reply when the user taps "Das nehme ich": `[products:<id>] Favorit: <name>` (confirm, offer next step).

- `price` is a JSON number in `currency` (a range or "ca." goes to `priceNote`); prices change: `priceNote` with the date, say "Preise ohne Gewähr" in text. Only prices/offers a tool returned. `specs` are `{label, value}` objects (not strings). Required: `id`, `source`, `basis:"sourced"`.
- `badge` only when the data supports it (test result, lowest price shown). Max 3 key `specs` for the question. `compare:true` for 3+ products.
- Comparing named buyable products ("X vs Y vs Z": phones, handhelds, headphones, appliances, cars; hint `format=products component=compare`): ALWAYS this node with `compare:true`, even for 2, never the generic `compare` node (it has no product photos, prices or specs table). Same spec labels on every product (the app lines them up as a table; up to 6 for a deep comparison), `pros`/`cons`, a `verdict` each, prices/`offers` only when a tool returned them. More than 10 named: the 10 most relevant, say so in text. Concepts, plans, services stay `compare`.
