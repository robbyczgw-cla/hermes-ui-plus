# Project website (hermesui.xyz)

A static site: no build step on the host, no JavaScript, no third-party requests. Light only, on purpose.

**Design: "The Messenger".** Hermes is the messenger god and the app icon is a chat bubble with golden wings, so the site reads like a printed dispatch on laid paper that comes alive with the app's interactive answers (tick, choose, approve; the tap goes back to Hermes): warm paper, ink, brass, and one sealing-wax red reserved for live and approval moments (the wax seal, "Allow once"). The hero plays `media/hero-loop-03.mp4` (the app's screen, cut by `make-hero.sh`) inside a CSS phone; the floating cards, the receipt, the stamps, the seal and the feather are HTML/CSS/inline SVG. The one page-load sequence (headline, phone, cards pinned, seal stamped), the interaction loop around the phone (a tap on "Allow once", a checklist item ticking, a choice being sent to Hermes) and every other loop are off under `prefers-reduced-motion`, which also replaces the hero video with its poster.

**Fonts** are self-hosted in `fonts/` (SIL Open Font License, licence texts next to them; `vercel.json` allows `font-src 'self'`), subset to Latin with [fonttools](https://github.com/fonttools/fonttools) `pyftsubset` (`--flavor=woff2`), about 57 KB together:

| File | Family | Role |
|---|---|---|
| `gloock-regular.woff2` | [Gloock](https://github.com/duartp/gloock) 400 | headlines, wordmark |
| `atkinson-hyperlegible-next-var.woff2` | [Atkinson Hyperlegible Next](https://github.com/googlefonts/atkinson-hyperlegible-next), variable 400–700 | text |
| `jetbrains-mono-var.woff2` | [JetBrains Mono](https://github.com/JetBrains/JetBrainsMono), variable 400–700 | commands, receipt, small labels |

The variable fonts were cut to `wght=400:700` with `fonttools varLib.instancer` before subsetting.

## Performance notes

- Posters are WebP (`media/*.webp`, made by `make-posters.sh` from the committed `media/*.jpg` masters); `trailer-poster.jpg` stays JPEG because it is the `og:image`. Run `make-posters.sh` after changing a poster.
- Sections below the hero use `content-visibility: auto` with measured `contain-intrinsic-size` (end of `style.css`), so the browser skips rendering the 23 videos and rotated plates until they are near the viewport. If a section's height changes noticeably, update its estimate (padding excluded) so in-page anchors still land on the section top.
- `vercel.json` keeps the CSP at `default-src 'none'` and adds only `connect-src 'self'`, which Lighthouse needs to fetch `robots.txt` (a page without it reports an invalid robots.txt). Media and fonts are cached for 30 days.

## Editing

The HTML files are generated and committed. After you change `PRIVACY.md`, `SECURITY.md`, `identity.json` or `build.mjs`:

```
node website/build.mjs           # rewrite the pages
node website/build.mjs --check   # fail when they are stale
node --test scripts/website.test.mjs   # also part of scripts/check.sh (stale pages, external requests, dead links)
```

When the platform status changes (a release is published, iOS or macOS ships), edit the Platforms table in `build.mjs` and rebuild.

## Demo videos

Posters (`media/*.jpg`, including `hero-loop-03.jpg`) are committed. The videos (`media/*.mp4`, about 130 MB) are too large for git (`.gitignore`) and are copied in or generated at deploy time from the demo export: the numbered clips for the demo reels (since 0.2 the bots clip is `bots-02.mp4`, 0.2 feature clip with music), `trailer-02.mp4` (16:9) and `trailer-02-vertical.mp4` (9:16) for the film block (general trailer with voice and music, recorded in the offline demo), `new-in-02.mp4` and `new-in-02-vertical.mp4` for the "New in 0.2" block (the 0.2 trailer), and the hero clip `hero-loop-03.mp4` (under 2 MB, autoplays muted; the old `hero-loop.mp4` stays reachable), which `make-hero.sh --raw` cuts from the recorder's raw 60 fps takes (since 0.3: four scenes, about 34 s, 1.6 MB; the trailers zoom and have a light backdrop, so the screen detection cannot read them). New file names for changed videos and posters: media is cached for 30 days. Keep the old `trailer.mp4`, `trailer-vertical.mp4` and `clip-wsp.mp4` in the deploy, links to them were shared:

```
cp dist/share/demos/[01][0-9]-*.mp4 dist/share/demos-20261015/[12][0-9]-*.mp4 dist/share/demos-20261015/trailer.mp4 website/media/
website/make-hero.sh --raw <takes>/bots/raw.mp4@9.0-17.0 <takes>/choice/raw.mp4@5.0-13.5 \
  <takes>/checklist/raw.mp4@16.0-26.0 <takes>/chart/raw.mp4@8.0-16.0   # HERO_NAME=hero-loop-03; raw takes (60 fps, 2x), OUT=<dir> to write elsewhere
website/make-hero.sh dist/share/demos-20261015/trailer-vertical.mp4      # or from an old-style vertical trailer (phone on a dark backdrop)
```

Without `--raw`, `make-hero.sh` finds the app's screen inside the trailer's phone and the scenes between the dark title, end and transition cards, joins the scenes with hard cuts (so the clip loops from the last scene straight into the first), crops it to the screen (540 px wide, 30 fps, H.264, no audio, faststart, at most 4 MB) and writes the first frame as `hero-loop.jpg`. ffmpeg runs in a memory-capped user scope (`systemd-run --user --scope -p MemoryMax=3G -p MemorySwapMax=0`, nice 10, 2 threads). The phone takes its proportions from the poster, so a trailer with a different screen size needs no CSS change. With a new trailer, run the script on it, then `node website/build.mjs` (the poster's size goes into the page) and commit the new `hero-loop.jpg`. The script header lists the overrides (`CROP`, `SEGMENTS`, `MAX_KB`, `CRF`) for a trailer it cannot read on its own.

A deploy from Git alone shows the poster frames only; the player then has nothing to play. Use the CLI deploy below, or host the videos somewhere else and rebuild with `WEBSITE_MEDIA_BASE=https://<media-host>/ node website/build.mjs` (then widen `media-src` in `vercel.json`).

## Deploy on Vercel (owner steps)

The domain's nameservers already point at Vercel (`ns1.vercel-dns.com`, `ns2.vercel-dns.com`), so DNS is managed in the Vercel dashboard (Domains), not at the registrar.

1. Vercel dashboard, **Add New > Project**, import the GitHub repository. Set **Root Directory** to `website`, **Framework Preset** to *Other*, leave build and install commands empty, output directory empty. Deploy. (Or from a checkout: `cd website && npx vercel link`.)
2. For the demo videos, copy them in (above) and deploy from the checkout: `cd website && npx vercel deploy --prod`. `.vercelignore` makes the CLI upload the git-ignored `media/*.mp4`.
3. Project **Settings > Domains**: add `hermesui.xyz` and `www.hermesui.xyz`. Make one the redirect target of the other (recommended: `www` redirects to the apex `hermesui.xyz`).
4. DNS: the domain uses Vercel nameservers, so Vercel creates the records itself once the domain is attached to a project. Check **Domains > hermesui.xyz > DNS Records**: an `A` record for `@` (the value Vercel shows, currently `76.76.21.21` or the project-specific IP it lists) and a `CNAME` for `www` (the value Vercel shows). If the domain is not in the project's team account yet, add it there first (Domains > Add). If you would rather keep DNS at the registrar, set exactly the records the Domains page asks for and switch the nameservers back to the registrar's.
5. Wait for the certificate (usually a minute). The project's Domains page shows **Valid Configuration** for both names.
6. Optional: e-mail. The domain has no MX record; the support address in `identity.json` is on another domain, so nothing is required.

Verify:

```
curl -sI https://hermesui.xyz/privacy | head -3     # HTTP/2 200
curl -sI https://www.hermesui.xyz/ | head -3        # redirect to https://hermesui.xyz/
curl -sI https://hermesui.xyz/privacy.html | head -3   # redirect to /privacy (cleanUrls)
```

Then tick item 3 in [docs/STORE.md](../docs/STORE.md) (privacy policy URL live). Before every store submission and after every release, rebuild so `/privacy` equals `PRIVACY.md` ([docs/RELEASING.md](../docs/RELEASING.md), step 10).

## Hardening

`vercel.json` sets `cleanUrls`, a strict Content-Security-Policy (`default-src 'none'`, own images, own media, own stylesheet), `nosniff`, `Referrer-Policy: no-referrer`, HSTS and a minimal Permissions-Policy. The site sets no cookies and loads nothing from third parties; there is no analytics.
